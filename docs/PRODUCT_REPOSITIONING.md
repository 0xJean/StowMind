# StowMind 产品重新定位方案

日期：2026-05-18

## 新定位

StowMind 从“AI 文件整理工具”升级为“智能清理与系统维护工具”。

核心定义：

> StowMind 是一个面向桌面用户的智能清理与系统维护工具，核心目标是释放空间、降低系统负担、发现占用来源；AI 文件整理是区别于传统清理工具的特色子功能。

一句话表达：

> Clean your Mac. Understand your files.

中文表达：

> 清理系统空间，也整理文件秩序。

## 定位变化

旧定位：

- 主功能：AI 文件整理。
- 辅助功能：重复文件、深度清理、统计。
- 竞争对象：文件整理器、下载目录整理器、AI 分类工具。

新定位：

- 主功能：清理、监控、磁盘分析、应用管理。
- 特色功能：AI 文件整理、语义归档、智能分类。
- 竞争对象：CleanMyMac、Sensei、DaisyDisk、AppCleaner、iStat Menus 的组合能力。

这意味着产品不再只回答“我的文件怎么分类”，而是回答：

- 为什么我的空间不够？
- 哪些东西可以安全清理？
- 哪些应用和进程拖慢了系统？
- 下载、桌面、项目目录为什么越来越乱？
- 能不能在清理之前帮我理解这些文件是什么？

## 迁移原则

重新定位应采用增量升级，不做破坏性替换。改造过程中必须保留现有能力：

- 保留现有 AI 文件整理流程，包括扫描、预览、执行、撤销、历史和设置。
- 保留现有重复文件扫描页面，但定位为辅助检查工具；除非 Mole 提供对应能力，否则不升级为核心清理执行功能。
- 保留现有 Deep Clean 页面中的 Mole 控制台方式，作为高级工具箱入口。
- 保留当前通过内置终端运行 `mo`、`mo clean`、`mo uninstall`、`mo optimize`、`mo analyze`、`mo status`、`mo purge`、`mo installer` 的方式。
- 新的清理体验应作为新增入口逐步上线，而不是直接替换旧入口；这里的“原生”指 StowMind 原生 UI 和工作流，不代表自研清理/删除器。
- 若未来 StowMind 原生页面覆盖 Mole 某些命令，也应继续保留 Mole Console 作为高级/兼容入口，除非明确决定下线。
- 核心清理能力必须基于 Mole 的真实命令或脚本函数；StowMind 只负责 UI、预览、确认、历史和统计，不直接实现清理删除逻辑。

## 产品支柱

### 1. Clean：空间清理

目标：帮助用户安全释放磁盘空间。

核心能力：

- 系统缓存清理。
- 应用缓存和日志清理。
- 开发构建产物清理。
- 安装包和下载残留清理。
- 废纸篓清理（仅在 Mole 能力覆盖时提供）。
- 大文件扫描。
- 重复文件辅助检查（只读，不作为 Mole 清理）。
- 应用残留清理。

设计原则：

- 默认预览，不直接删除。
- 执行阶段必须调用 Mole 自身的清理命令或函数，不引入 StowMind 自研删除路径。
- 高风险项默认不选。
- 每个清理项解释来源、影响和可恢复性。
- 支持排除路径和本次跳过。

### 2. Monitor：资源监控

目标：让用户知道系统负担来自哪里。

核心能力：

- CPU、内存、磁盘、网络实时状态。
- GPU、温度、电池、运行时间。
- 进程占用排行。
- 菜单栏轻量状态。
- 健康评分。
- 异常提醒，如内存压力高、磁盘空间不足、后台进程异常占用。

设计原则：

- 监控是为了引导清理和优化，不做复杂运维面板。
- 菜单栏显示保持克制，避免噪音。
- 所有建议都应能落到一个具体动作：清理、关闭、查看、忽略。

### 3. Optimize：系统优化

目标：提供保守、安全、可解释的维护动作。

核心能力：

- 启动项和登录项检查。
- Launch Agents / Daemons 检查。
- 无效残留项提示。
- Spotlight、Quick Look、DNS、字体缓存等维护任务。
- 权限状态检查，如完全磁盘访问。

设计原则：

- 优化能力分普通和高级两层。
- 高级操作必须解释风险。
- 不做“神奇加速”文案，只展示具体动作。

### 4. Apps：应用管理

目标：帮助用户理解应用占用和残留。

核心能力：

- App 列表。
- 应用体积、缓存体积、最近使用时间。
- 大型 App、长期未使用 App 提醒。
- App 卸载。
- 残留文件扫描。

设计原则：

- 卸载和残留清理必须逐项预览。
- 不自动删除用户文档、账号数据、配置。
- 对安全软件、同步盘、开发工具给出特殊警告。

### 5. Organize：AI 文件整理

目标：处理传统清理工具不擅长的“文件语义混乱”问题。

核心能力：

- 下载目录智能分类。
- 桌面、文档、项目目录整理。
- 文件语义归档。
- 相似文件分组。
- 归档建议。
- 清理前解释文件用途。

设计原则：

- 规则优先，AI 处理疑难项。
- 所有移动操作先预览。
- 支持撤销和历史。
- AI 只用于分类与解释，不应直接决定删除。

## 新信息架构

建议主导航：

1. Dashboard
2. Clean
3. Monitor
4. Analyze
5. Apps
6. Organize
7. History
8. Settings

页面说明：

- Dashboard：空间、健康评分、最近问题、推荐动作。
- Clean：Mole 清理中心，聚合系统缓存、构建产物、安装包、废纸篓等 Mole 支持的清理项。
- Monitor：资源状态、进程、菜单栏设置。
- Analyze：磁盘空间地图、大文件、目录占用。
- Apps：应用列表、卸载、残留。
- Organize：现有 AI 文件整理能力。
- History：所有清理、整理、卸载、优化操作历史。
- Settings：权限、排除项、AI、主题、语言、安全策略。

## MVP 路线图

### M0：定位修正

目标：先让产品表达和现有能力对齐。

- 更新 README、首页文案、导航命名。
- 把 Deep Clean 从“附属功能”提升为主功能入口。
- 明确 Mole 当前是外部 CLI 工具箱。
- 明确 Mole Console 入口继续保留，不因原生清理能力上线而删除。
- 建立统一术语：清理、监控、分析、整理。

### M1：清理中心

目标：形成真正的核心功能。

能力范围：

- 构建产物扫描和清理，基于 Mole purge。
- 安装包扫描和清理，基于 Mole installer。
- 废纸篓大小展示，基于 Mole status / clean 输出。
- 重复文件保持辅助检查，只展示和打开路径，不执行清理。
- 大文件扫描，优先基于 Mole analyze。

验收标准：

- 所有项目有大小、路径、类型、风险等级。
- 所有核心清理执行都必须调用 Mole 的真实命令或函数。
- StowMind 不直接删除文件，不提供自研废纸篓适配器作为核心清理执行路径。
- 所有操作写入 History。
- 清理前有确认，清理后有结果汇总。

Mole 对接原则：

- 核心清理能力必须对接 Mole 的真实命令或脚本函数，不做假数据，也不做平行自研清理实现。
- 已支持 JSON 的命令直接结构化接入，例如 `mo status -json`、`mo analyze -json`。
- 只有 dry-run 文本/TUI 输出的命令先通过适配器解析预览，例如 `mo clean --dry-run`、`mo purge --dry-run`、`mo installer --dry-run`。
- 当前已接入 `mo clean --dry-run` 系统清理预览、`mo status -json` 资源状态、`mo analyze -json <path>` 磁盘分析、限定目录的 Mole purge dry-run / execute，以及复用 Mole installer 扫描 / execute 函数的安装包清理。
- `mo clean` 这类高权限系统清理执行阶段仍走现有 Mole Console，直到能安全包装 Mole 自身确认流程。
- Mole Console 全程保留。

### M2：Dashboard 和磁盘分析

目标：让用户进入应用后立即知道问题在哪里。

能力范围：

- 磁盘剩余空间。
- 可清理空间估算。
- 最大目录和最大文件。
- 最近清理收益。
- 推荐动作。
- 目录占用分析列表。

验收标准：

- 首页不再只是快捷入口，而是系统状态摘要。
- 从每个推荐项可以直接进入具体清理页面。

### M3：资源监控

目标：建立“系统维护工具”的感知能力。

能力范围：

- CPU、内存、磁盘、网络。
- GPU、温度、更多状态信号。
- 进程占用排行。
- 菜单栏状态。
- 内存压力和磁盘空间提醒。

验收标准：

- 监控数据不依赖终端。
- 后台开销可控。
- 用户可以关闭菜单栏和提醒。

### M4：应用管理

目标：覆盖 CleanMyMac/AppCleaner 高频场景。

能力范围：

- App 列表。
- App 体积与缓存估算。
- 最近使用时间。
- 卸载预览。
- 残留扫描。

验收标准：

- 高风险残留默认不选。
- 系统 App 和安全软件默认保护。
- 操作写入 History。

### M5：系统优化

目标：提供高级用户维护能力。

能力范围：

- 启动项检查。
- 无效 Launch Agent 检查。
- DNS、Quick Look、Spotlight 等维护任务。
- 权限诊断。

验收标准：

- 普通用户不会误触高风险操作。
- 每个优化项有解释、风险和恢复建议。

## Mole 集成策略

新定位下，Mole 的角色从“边缘集成”变成“核心清理能力来源”。StowMind 可以把体验做成原生页面，但清理数据和清理执行必须来自 Mole。

短期：

- 保留 Mole CLI 工具箱。
- 用 Mole 的真实能力验证用户需求和清理类别。
- 对系统优化、卸载等复杂功能先借助 Mole 作为高级入口。

中期：

- 对高频清理场景做 StowMind 原生 UI。
- 对 Mole 命令和脚本函数做适配器封装，逐步减少终端交互。
- 把扫描结果接入 StowMind 的预览、确认、历史、统计。

长期：

- 核心清理继续保持 Mole-backed；StowMind 原生化的是 UI、工作流和记录体系。
- Mole Console 保留为高级用户兼容入口。

## 差异化策略

传统清理工具强在系统维护，但弱在文件语义。StowMind 的差异化应该是：

- 清理前能解释文件是什么。
- 不只是删，还能整理和归档。
- 对下载目录、桌面、项目目录更聪明。
- 规则和 AI 结合，降低误判。
- 所有操作可预览、可追溯、尽量可恢复。

可以形成一个核心体验：

1. 扫描系统和用户目录。
2. 找出可释放空间和混乱目录。
3. 对缓存、构建产物、安装包等直接清理。
4. 对用户文件提供整理建议，而不是删除建议。
5. 对重复和大文件给出保留建议。
6. 操作后形成清理报告。

## 关键风险

### 产品风险

- 进入系统清理赛道后，用户期望会显著提高。
- 功能变多后容易失去“简单可信”的感觉。
- AI 整理可能被弱化，需要明确特色位置。

### 技术风险

- macOS 权限和系统路径会持续变化。
- 系统级清理误删风险高。
- 资源监控和菜单栏需要控制后台开销。
- App 卸载残留规则维护成本高。

### 信任风险

- 清理工具天然需要用户授予高权限。
- 一次误删就会破坏产品信任。
- 如果混用 Mole CLI、Mole 脚本函数和 StowMind 原生 UI，需要明确来源和责任边界。

## 决策建议

建议确认新定位，并按以下顺序推进：

1. 先改产品表达和导航，让“清理”成为主线。
2. 先做文件空间相关清理，不急着做系统优化。
3. 用 Dashboard 串联清理、监控、分析、整理。
4. 把 AI 整理包装成清理后的高级动作：不能删的用户文件，帮用户整理。
5. 保留 Mole Console 作为高级工具箱；核心体验逐步做成 StowMind 原生页面，但清理执行仍基于 Mole。

最终目标不是复制 CleanMyMac，而是做一个更懂用户文件的智能清理工具。
